# 퀘스트 보드 시각 검증 체크리스트

이 체크리스트는 테스트로 검증할 수 없는 UI 동작을 수동으로 확인하는 절차입니다. **한 번의 앱 실행으로 모두 확인 가능하도록 구성했습니다.**

---

## 준비

```bash
cd Packages/Jirarcade
swift run JirarcadeApp
```

앱이 띄워지고 로그인 → 워크플로 매핑 → 아케이드 플로어까지 진행합니다.

## 1. 아케이드 플로어 구성 (Task 8)

### 1.1 캐비닛 목록 확인
- [ ] QUEST BOARD 카드가 보인다
- [ ] OBSERVATION 카드가 보인다  
- [ ] 세 번째 슬롯에 "coming soon" 플레이스홀더 하나만 있다 (중복 없음)

### 1.2 퀘스트 보드 전체 화면 전환
- [ ] QUEST BOARD의 "▶ OPEN" 버튼을 누른다
- [ ] 보드가 전체 화면으로 띄워진다 (플로어 배치는 사라짐)
- [ ] 상단에 "◂ FLOOR" 버튼과 제목이 있다
- [ ] 제목 아래 구분선이 있다
- [ ] "◂ FLOOR" 버튼을 누른다
- [ ] 플로어로 돌아간다
- [ ] 전체 화면 상태에서 Esc를 누른다
- [ ] 플로어로 돌아간다

### 1.3 OBSERVATION 카드 (기존 동작, 시트 방식)
- [ ] OBSERVATION의 "▶ OPEN" 버튼을 누른다
- [ ] 관측 상세가 시트로 띄워진다 (플로어 배치는 남아 있음)

## 2. 보드 축과 레인 렌더링 (Task 9)

이 항목은 QUEST BOARD 전체 화면이 띄워진 상태에서 확인합니다.

### 2.1 축 범위와 눈금
- [ ] 보드의 좌측에 시간축이 그려진다
- [ ] 축에 일차 레이블 (예: 0d, 7d, 14d 등)이 있다
- [ ] 각 레이블의 위치가 균등하게 분포한다

### 2.2 상태별 레인
- [ ] 보드가 상태 레인들로 나뉜다 (BACKLOG, ACTIVE, REVIEW, VERIFY)
- [ ] 각 레인의 헤더에 상태명이 쓰여 있다
- [ ] 헤더 오른쪽에 티켓 개수가 표시된다 (예: "4")

### 2.3 카드 배치
- [ ] 각 카드가 정체일에 따라 축 위에 배치된다
- [ ] 같은 레인에서 두 개 이상의 카드는 겹치지 않는다 (필요하면 아래로 쌓인다)
- [ ] 카드의 좌측 가장자리가 축의 시작점(0d)에 가깝고, 우측이 축의 끝에 가깝다

### 2.4 윈도우 크기 조정 시 카드 배치
- [ ] 앱 윈도우를 매우 좁게 줄인다 (예: 300pt 정도)
- [ ] 카드들이 여전히 겹치지 않고 수직으로 쌓인다
- [ ] 가독성이 손상되지 않는다

### 2.5 빈 레인
- [ ] 티켓이 없는 레인이 있는 경우, 그 레인도 축 선과 눈금이 보인다
- [ ] "여기에 아무것도 없다" 같은 메시지나 상태가 시각적으로 명확하다

### 2.6 카드 높이 변경(112 → 120pt) 후 레인 간격 (Task 13, 이월 표시)
카드에 이월 줄이 추가되면서 `BoardMetrics.cardHeight`가 112 → 120pt로 늘었다.
`laneHeight = rowCount × cardHeight`라서 이 변화는 이월이 없는 카드가 있는 레인을
포함해 **보드의 모든 레인**에 영향을 준다.
- [ ] 카드 한 장의 세로 폭이 커진 만큼, 레인 헤더와 그 아래 첫 줄 카드 사이 간격이 시각적으로 어색하지 않다
- [ ] 한 레인에 카드가 여러 줄로 쌓일 때(§2.3), 줄 사이 간격(`rowGap`)이 카드 높이 변화와 무관하게 일정하다
- [ ] 레인이 여러 개일 때 레인 사이 경계가 겹치거나 잘리지 않는다
- [ ] 이월 줄이 있는 카드와 없는 카드가 같은 레인, 같은 줄에 섞여 있어도 카드 하단이 서로 어긋나지 않는다(모든 카드가 `cardHeight`로 고정 높이라 정렬은 유지돼야 한다)

## 3. 보드 HUD (Task 10)

QUEST BOARD 전체 화면의 최상단을 확인합니다.

- [ ] 레벨 숫자가 보인다
- [ ] XP 진행률 바가 보인다
- [ ] 연속 일수 카운터가 보인다

### 3.2 위생 섹션

- [ ] HP 아이콘 (하트)이 최대 3개까지 보인다

## 4. 상태 전이 메뉴와 카드 애니메이션 (Task 11)

**중요: 이 섹션은 특별히 주의해서 검증하세요. 다음 항목 4.1과 4.2는 구현 위험이 존재합니다.**

### 4.1 ✓ **전이 메뉴는 매번 새로 불러와야 함 (캐싱 금지)**

**목표**: 메뉴가 열릴 때마다 Jira 워크플로 후보를 새로 가져온다는 것을 확인.

**과정**:
1. 카드 하나를 선택하고 "상태 옮기기" 메뉴를 연다
2. 로딩 상태 ("불러오는 중…") 또는 후보 목록이 표시되는 것을 본다
3. 메뉴를 닫는다 (Esc 또는 다른 곳 클릭)
4. **같은 카드의 메뉴를 다시 연다**
5. 로딩 상태가 **다시 나타나는지 확인한다**

**기대**: 로딩 상태가 두 번째 열때도 나타난다 (캐시되지 않음).

**만약 안 된다면**: 
- 메뉴가 처음 열 때만 로딩되고 두 번째에는 즉시 목록이 보인다면 캐싱 문제가 있다
- 이 경우 admin이 Jira 워크플로를 변경했을 때 앱이 잘못된 상태로 전이를 시도할 수 있다

### 4.2 ✓ **카드 높이와 실패 메시지 표시 (클리핑 금지)**

**목표**: 카드의 높이가 충분해서 전이 실패 시 모든 정보를 볼 수 있다.

**과정**:
1. 마감일 라벨이 있는 카드를 찾는다
2. 해당 카드의 "상태 옮기기" 메뉴에서 다음 상태를 선택해 전이를 요청한다
3. 또는 전이가 실패하도록 유도한다 (admin이 워크플로를 변경하거나 다른 방법)
4. 카드에 실패 메시지가 표시된다
5. **마감일 라벨이 사라지고 그 자리에 실패 메시지가 나타난다** (마감일과 실패는 동시에 보이지 않음)
6. 실패 메시지 전체, "Jira에서 열기" 링크, "닫기" 버튼이 모두 **카드 아래쪽이 잘리지 않고** 한 줄에 보인다
7. **"닫기" 버튼을 누르면** 실패 블록이 사라지고 마감일 라벨과 "상태 옮기기" 메뉴가 다시 나타난다 (또는 다른 전이를 시도해도 같은 결과)

**기대**: 실패 메시지 블록의 모든 줄(실패 이유 + "Jira에서 열기"·"닫기" 행)이 완전히 보인다. 카드 높이(현재 120pt — 이월 줄이 추가되며 112pt에서 조정됨)는 이를 위한 것이다. "닫기"는 `jiraURL`이 없을 때(사이트 호스트를 아직 못 받았을 때)도 항상 보여야 한다 — 그렇지 않으면 실패한 카드가 세션 내내 메뉴를 다시 열 방법이 없다.

**만약 안 된다면**: 
- 실패 메시지나 "Jira에서 열기" 링크가 카드 아래에서 잘린다면, 사용자가 왜 전이가 실패했는지 알 수 없고 Jira에서 추가 정보를 찾을 수 없게 됨.
- "닫기" 버튼이 없거나 눌러도 실패 블록이 사라지지 않는다면, 그 카드는 실패가 뜬 순간부터 세션이 끝날 때까지 "상태 옮기기" 메뉴로 돌아갈 방법이 없어 다른 전이를 시도할 수 없게 됨.

### 4.3 카드의 스프린트 이월 표시 (Task 13)

**목표**: 이월 줄이 있어야 할 때만 정확히 나타나고, 카드가 가장 붐빌 때도 다른 정보와 함께 잘리지 않는다는 것을 확인.

**과정**:
1. 두 번 이상 스프린트가 바뀐 티켓의 카드를 찾는다
2. 카드에 `↻ 스프린트 N회` 줄이 보이는지 확인한다
3. 그 줄에 마우스를 올려(hover) 툴팁이 뜨는지, 첫 스프린트 → 마지막 스프린트 이름이 "이름 → 이름" 형태로 보이는지 확인한다
4. 스프린트를 한 번도 안 바꿨거나(0회) 아예 스프린트가 없는 티켓의 카드를 찾는다 — 이월 줄이 아예 없고, 그 자리에 빈 간격도 남지 않는지(다른 줄들이 그 공간까지 채우며 배치되는지) 확인한다
5. 마감일이 있고 이월도 있는 티켓의 "상태 옮기기" 메뉴를 연다 — 마감일 줄 + 이월 줄 + 메뉴가 모두 뜬 상태(카드가 가장 빽빽한 조합)에서 카드 아래쪽이 잘리지 않는지 확인한다
6. 이월이 있는 티켓에서 전이를 요청해 5초 대기 배너를 띄운다 — 대기 중에도 이월 줄이 계속 보이는지 확인한다
7. 이월이 있는 티켓에서 전이를 실패시킨다(§4.2와 같은 방법) — 실패 블록이 뜨는 동안 이월 줄이 사라지는지 확인한다(마감일 줄과 같은 자리 경쟁)

**기대**: 이월 표시는 정보가 있을 때만 자리를 차지한다. 대기 중에는 마감일 줄과 함께 계속 보이고, 실패 블록이 뜨는 동안만 마감일 줄과 함께 숨는다(`TicketCardView.showsFailureBlock`, 최종 전체 브랜치 리뷰 Finding 5). 카드가 가장 붐빌 때(마감일 + 이월 + 메뉴)도 어느 줄도 잘리지 않는다.

**만약 안 된다면**:
- 이월이 0인 카드에 빈 줄이나 빈 간격이 남는다면, 카드 높이 예산이 쓸모없이 낭비되고 있다는 뜻이다.
- 가장 빽빽한 조합에서 무언가 잘린다면 `BoardMetrics.cardHeight`(이 문서 §2.6 참고)를 다시 재야 한다.
- 대기 중에 이월 줄이 사라진다면 "대기 중에는 숨기지 않는다"는 규칙(설계문서 §6)이 깨진 것이다.

## 5. 카드 상태 전이 동작 (Task 11)

### 5.1 낙관적 이동과 애니메이션
- [ ] 카드의 "상태 옮기기" 메뉴를 열고 다음 상태를 선택한다
- [ ] 카드가 **즉시** 새 상태 레인으로 이동한다 (로딩 대기 없음)
- [ ] 카드의 이동이 부드러운 스프링 애니메이션으로 보인다

### 5.2 5초 카운트다운 취소 윈도우
- [ ] 전이 후 카드에 "취소" 버튼이 있는 pending 배너가 표시된다
- [ ] 배너에 대상 상태가 쓰여 있다
- [ ] 배너에 **남은 시간이 초 단위로("5s" 형태) 표시되고 매초 줄어든다** — 5 → 4 → 3 → …
- [ ] 카운트다운이 줄어드는 동안 카드의 다른 줄(요약·마감일 등)은 다시 그려지지 않는다(깜빡임 없음)
- [ ] "취소" 버튼을 누른다
- [ ] 카드가 **원래 레인으로 돌아온다** (애니메이션됨)
- [ ] Jira 웹에서 보면 상태가 변경되지 않았다 (앱이 실제 요청을 보내지 않음)

### 5.3 5초 후 자동 전이
- [ ] 다시 카드에서 "상태 옮기기" → 상태를 선택한다
- [ ] Pending 배너가 표시되고 **5초 동안 기다린다** (시계로 확인)
- [ ] 5초가 지나면 배너가 사라진다
- [ ] Jira 웹에서 확인하면 상태가 실제로 변경되었다
- [ ] 앱을 다시 동기화하면 카드에 XP가 붙는다

### 5.4 Reduce Motion 설정
- [ ] macOS 시스템 설정 > 손쉬운 사용 > 디스플레이 > 동작 줄이기 를 켠다
- [ ] 앱으로 돌아간다
- [ ] 카드에서 "상태 옮기기" → 상태 선택
- [ ] 카드가 **애니메이션 없이 즉시** 새 레인으로 옮겨진다 (스프링 효과 없음)
- [ ] "취소"를 눌러 원래 상태로 돌아올 때도 즉시 옮겨진다 (애니메이션 없음)

## 6. 매핑되지 않은 티켓 레인 (Task 12)

### 6.1 매핑된 상태와 미매핑된 상태
- [ ] 일부 티켓의 상태가 **워크플로 매핑 시 연결되지 않았다** (또는 테스트용으로 특정 상태를 매핑 해제한다)
- [ ] 그러한 티켓들이 보드에 **사라지지 않고** 별도의 "매핑되지 않은 티켓" 레인에 표시된다

### 6.2 미매핑 레인 기본 상태 (접혀 있음)
- [ ] 보드 최하단에 "매핑되지 않은 티켓" 섹션이 보인다
- [ ] 섹션이 **기본적으로 접혀 있다** (화살표 또는 expand 표시)
- [ ] 티켓 개수가 "N건" 형태로 표시된다

### 6.3 미매핑 레인 펼치기
- [ ] "매핑되지 않은 티켓" 섹션의 헤더를 클릭하거나 expand 버튼을 누른다
- [ ] 미매핑 상태의 모든 티켓이 목록으로 표시된다
- [ ] 각 티켓에 key, 상태명(미매핑 상태), 요약이 표시된다

### 6.4 매핑 고치기
- [ ] 미매핑 레인에 "매핑 고치기" 버튼이 있다
- [ ] 버튼을 누른다
- [ ] 워크플로 매핑 마법사 화면이 띄워진다
- [ ] 매핑을 변경하고 완료한다
- [ ] 다시 퀘스트 보드로 돌아온다
- [ ] 미매핑 레인의 티켓들이 사라지고 적절한 상태 레인에 표시된다 (또는 티켓 개수가 줄어든다)

## 7. 빈 상태 (Task 12)

### 7.1 동기화 전 (처음 실행, 또는 데이터 삭제 후)
- [ ] 동기화를 아직 하지 않은 상태에서 퀘스트 보드를 연다
- [ ] "아직 동기화하지 않았습니다"라는 메시지가 보인다

### 7.2 동기화 후, 담당 미완료 티켓 없음

  (또는 테스트 계정이 그런 상태라면 그대로 확인)
- [ ] 보드가 비어 있고 "담당한 미완료 티켓이 없습니다"라는 메시지가 보인다
- [ ] 추가 안내문 (예: "Jira에서 티켓을 맡으면 여기에 나타나요")이 있으면 함께 표시된다

### 7.3 매핑되지 않은 티켓만 있는 경우

- [ ] 메인 레인은 비어 있고 (빈 상태 메시지 표시)
- [ ] **"매핑되지 않은 티켓" 레인은 여전히 보인다** (경계 예시: 사용자가 매핑 없이도 이 티켓들을 관리할 수 있음)

## 11. 티켓 상세 시트 (Task 12, [티켓 상세 설계](../specs/2026-08-24-ticket-detail-design.md))

이 섹션은 QUEST BOARD가 열린 상태에서 카드 하나를 골라 확인합니다. `ArcadeUI`에는 테스트 타깃이 없으므로
시트·댓글 목록·카드의 새 탭 대상은 전부 이 체크리스트로만 확인됩니다.

**2026-08-25 1차 확인:** 실계정(티켓 45건)에서 아래 표시된 항목을 확인했습니다. 확인하지 못한 항목은
필요한 데이터(표·첨부가 있는 본문, 댓글이 둘 이상인 티켓)나 실패 상황을 만들지 못해 남겨 둡니다.

### 11.1 카드의 탭 대상과 기존 컨트롤 (회귀)

티켓 키가 `.plain` 스타일의 `Button`이 되면서 카드 전체가 아니라 키만 시트를 여는 탭 대상이 됐다
(`TicketCardView.swift`). 나머지 컨트롤이 이 변경으로 클릭을 가로채이지 않는지 확인한다.

- [x] 카드의 티켓 키(모노스페이스 굵은 글씨)를 누르면 티켓 상세 시트가 열린다
- [x] 시트의 `닫기`를 누르면 시트가 닫히고 보드로 돌아간다 (Escape로도 닫힌다)
- [x] 같은 카드에서 `상태 옮기기` 메뉴가 그대로 열린다(키를 눌러 시트가 열리는 것과 헷갈리지 않는다)
      — 전이 후보 17개가 전부 뜨고, 이름과 도착 상태가 다른 항목은 `검토 중 → STAG 반영`처럼 둘 다 보인다
- [ ] 전이를 요청해 대기 배너를 띄우고 `취소`를 누르면 원래 레인으로 돌아온다(§5.2 참고)
- [ ] 전이를 실패시켜 실패 블록을 띄우고 `Jira에서 열기`가 브라우저를 연다
- [ ] 실패 블록의 `닫기`를 누르면 블록이 사라지고 카드가 평소 모습으로 돌아온다

### 11.2 본문 렌더링

- [x] 본문이 있는 티켓의 시트를 열면 본문이 평문으로 보인다
      — 문단이 빈 줄로 구분되고, 문단 안 줄바꿈이 유지되며, `rule` 노드가 `———`으로 그려진다
- [x] 본문이 없는(`description`이 비어 있거나 `null`인) 티켓은 "본문이 없습니다"가 보인다
- [ ] 표가 있는 본문은 표 내용 대신 `[표]` 자리표시자가 보이고, 그 앞뒤 문단은 그대로 보인다
      (표 하나 때문에 본문 전체가 사라지지 않는다)
- [ ] 첨부(이미지 등)가 있는 본문은 `[첨부]` 자리표시자가 보인다
- [ ] 렌더러가 모르는 서식(패널·확장 블록 등 Jira가 최근 추가한 노드)이 있으면
      `[지원하지 않는 서식]` 자리표시자가 보이고, 나머지 문단은 그대로 보인다 — 조용히 사라지지 않는다

**확인하지 못한 것:** 표·첨부·미지의 서식이 있는 본문을 실계정에서 찾지 못했습니다. 자리표시자 세 개는
단위 테스트(`ADFRendererTests`)가 덮지만 화면에서는 확인하지 못했습니다.

### 11.3 댓글 목록

- [ ] 댓글이 둘 이상 있는 티켓에서 시트를 열면 **최신 댓글이 맨 위**에 보인다
- [ ] 각 댓글에 작성자·날짜·본문이 보인다

### 11.4 제목 수정과 저장

- [x] 시트를 열면 제목 입력란에 현재 제목이 채워져 있다
- [ ] 제목 입력란의 값을 바꾸면 `제목 저장` 버튼이 활성화된다
- [ ] 값을 원래 제목으로 되돌리면 버튼이 다시 비활성화된다(변경 없음으로 판단)
- [ ] `제목 저장`을 누르고 완료를 기다리면(동기화가 끝난 뒤) 카드의 요약 줄이 새 제목으로 바뀐다
- [ ] Jira 웹에서 확인해도 제목이 실제로 바뀌어 있다

### 11.5 저장 중 잠금

- [ ] `제목 저장`을 누른 직후(응답이 오기 전) 그 버튼과 `댓글 등록` 버튼이 둘 다 눌리지 않는 상태로 보인다
- [ ] 응답이 온 뒤에는 다시 눌린다(성공이든 실패든)
- [ ] 저장 버튼을 빠르게 두 번 눌러도 Jira에 요청이 한 번만 나간다
      (가능하면 Jira 쪽 변경 이력이나 감사 로그로 확인)

### 11.6 저장 실패 문구

- [ ] 저장이 거부되도록 유도한다(예: 제목을 매우 길게 입력)
- [ ] 실패 문구가 뜨고, 그 문구에 Jira 응답 본문 조각(에러 메시지 원문, 이메일 등)이 섞여 있지 않다 —
      앱이 직접 쓴 짧은 문장이어야 한다
- [ ] 실패 문구 옆 `닫기`를 누르면 실패가 사라지고 다시 저장을 시도할 수 있다

### 11.7 댓글 등록

- [ ] 댓글 입력창에 글을 쓰고 `댓글 등록`을 누르면 성공 후 목록 맨 위에 새 댓글이 나타나고 입력창이 비워진다
- [ ] 등록이 실패하도록 유도한다(권한 없는 티켓 등) — 실패해도 **입력창의 글이 그대로 남는다**(지워지지 않는다)
- [ ] 공백만 입력하고 누르면 아무 일도 일어나지 않는다(버튼이 비활성화돼 있거나 눌러도 반응이 없다)

### 11.8 포커스 링 (판단이 필요 — 주의해서 볼 것)

티켓 키가 `.plain` 스타일의 `Button`이 되면서 카드마다 Tab 정지점이 하나 늘었고, 포커스를 받으면
링이 그려질 수 있다. 옳고 그름이 정해진 항목이 아니라 **눈으로 보고 판단할 것.**

- [ ] Tab 키로 카드들 사이를 이동하면 티켓 키에 포커스 링이 보이는지 확인하고 결과를 기록한다
      (보이거나 안 보이거나, 어느 쪽이든 기록이 필요하다)
- [ ] 포커스 링이 보인다면 카드의 다른 요소(등급 배지·정체일 라벨)와 겹치거나 잘리지 않는다
- [ ] 포커스 상태에서 Enter나 Space를 누르면 시트가 열린다

### 실계정 전이 테스트 (MPT-9563, 2026-08-24)

`--restore-window`를 붙이면 메뉴 팝업도 접근성 트리에 잡힌다(첫 시도에서 실패한 것은 그
플래그가 없었기 때문이다). 실제로 전이를 두 번 실행해 Jira 반영까지 확인했다.

| 항목 | 결과 |
|---|---|
| §5.1 낙관적 이동 | 확인 — 카드에 `→ STAG 반영` / `→ 진행 중` 대기 배너 |
| §5.2 5초 내 취소 | 확인 — 사용자가 직접 검수 |
| §5.3 5초 후 자동 전이 | 확인 — 11:38 `진행 중 → STAG 반영`, 11:42 원복. 둘 다 Jira API로 반영 확인 |
| §4.1 메뉴 재요청 | 부분 확인 — `.onAppear`가 발화하고 후보 17건을 실제로 받아온다(1회차 "불러오는 중…" → 2회차 목록). **"매 열기마다"인지는 미확정** — 메뉴가 클릭마다 토글되고 `get-app-state`가 메뉴를 닫아, 관찰 창이 클릭 응답 스냅샷 하나뿐이다 |

**이 테스트가 실제 결함을 하나 잡았다.** 메뉴에서 "검토 중"을 골랐는데 티켓이 "STAG 반영"으로
갔다. `JiraTransition`의 전이 이름(`name`)과 도착 상태(`toStatusName`)가 다른 워크플로였고,
메뉴가 이름만 보여주고 있었다. 자동 테스트의 픽스처는 늘 둘이 대응하는 데이터였기 때문에
실데이터에서만 드러났다 — 시각 확인이 존재하는 이유다.
고친 뒤로 메뉴는 둘이 다를 때 `검토 중 → STAG 반영`처럼 함께 보여준다
(`JiraTransition.menuLabel`, `TransitionLabelTests`가 고정).

### 카드의 스프린트 이월 표시 확인 (최종 전체 브랜치 리뷰 Finding 2, 2026-08-24)

실계정 데이터로 §4.3의 항목을 확인했다.

| 항목 | 결과 |
|---|---|
| §4.3 이월 줄 렌더링 | 확인 — `↻ 스프린트 N회` 형태로 표시됨 |
| §4.3 이월 0회 카드 | 확인 — 줄도 빈 간격도 없음 |
| §4.3 가장 빽빽한 조합 | 확인 — 마감일 + 이월 줄 + "상태 옮기기" 메뉴가 한 카드에 동시에 뜬 상태에서 잘리지 않음 |
| §4.3 툴팁(첫 → 마지막 스프린트 이름) | **보류** — 아래 "도구 한계로 확인 불가" 참고 |

### 도구 한계로 확인 불가

- **§2.4 좁은 창 배치** — `capabilities`의 `windows.moveResize: false`. 창 크기를 바꿀 수 없다.
- **스크린샷 전반** — `get-app-state`가 `screenshot` 필드를 돌려주지 않았다.
- **§4.3 이월 툴팁** — SwiftUI `.help()`는 접근성 트리에 노출되지 않고, hover 제스처는 이
  환경(CLI 기반 computer-use)에서 재현할 수 없다. 첫 → 마지막 스프린트 이름이 맞는 순서로
  뜨는지는 사람이 직접 카드에 마우스를 올려 확인해야 한다.

### 조건이 없어 확인 불가

- **§6 미매핑 티켓 레인** — 현재 계정의 모든 상태가 매핑돼 있어 미매핑 티켓이 0건이다.
  레인이 뜨지 않는 것이 정상 동작이며, 레인 자체는 미매핑 상태가 생겨야 볼 수 있다.
- **§2.5 빈 레인** — 네 레인 모두 티켓이 있다.

### 자동 확인 시 알아둘 것

`swift run JirarcadeApp`으로 띄운 프로세스는 **접근성 API에 창이 보이지 않는다**
(`window_not_found`). 번들 없이 실행하면 백그라운드 전용 앱으로 등록되기 때문이며,
앱이 활성화 정책을 `.regular`로 올려도 접근성 쪽에서는 잡히지 않았다.
`./scripts/make-app.sh --open`으로 번들을 만들면 `dev.jirarcade.app` 번들 ID를 갖고 정상 동작한다.
**UI 자동 검증은 번들로 띄워야 한다.**
