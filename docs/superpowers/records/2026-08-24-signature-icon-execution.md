# 앱 시그니처 아이콘 — 실행 기록

계획: `docs/superpowers/plans/2026-08-24-signature-icon.md`

계획대로 다섯 태스크를 끝냈다. 아래는 **실행 중에 계획과 달라진 것**과 그 이유다.
전부 렌더를 눈으로 보고 되돌린 것들이라, 기록해 두지 않으면 다음 사람이 같은 자리에서
같은 판단을 다시 해야 한다.

## 1차 렌더가 태블릿으로 보였다

계획의 기하는 캐비닛을 **직사각형 하나**(본체 + 조작판 밴드)로 잡았다. 그렸더니
"amber 화면 달린 기기"였다 — 아케이드 캐비닛이 아니었고, 어느 앱의 아이콘이어도
이상하지 않은 그림이었다.

**바꾼 것:** 조작판을 밴드에서 빼내 **본체보다 넓은 별도 단**(`controlDeck`)으로 만들었다.
실루엣에 계단이 하나 생기고, 그 계단 하나가 색보다 많은 일을 한다. 16px에서도 남는다.

`Band`는 다섯(마퀴·틈·화면·틈·조작판)에서 셋(마퀴·틈·화면)으로 줄었다.

## 경첩 글자가 화면 밴드를 넘었다

`NSString.draw(at:)`의 기준점은 베이스라인이 아니라 **라인 프래그먼트의 왼쪽 아래**다.
베이스라인은 거기서 `descender`만큼 위에 있고 `descender`는 음수다. 부호를 뒤집어 써서
글자가 |descender|만큼 위로 밀려 마퀴 밴드까지 올라갔다.

**바꾼 것:** `y = screen.midY - capHeight/2 + font.descender`.

## 마퀴와 화면이 한 덩어리로 뭉쳤다

둘 다 accent로 꽉 채우니 "amber 판에 줄 하나 그은 것"으로 보였다. 틈(본체 높이의 3%)은
긁힌 자국 같았다.

**바꾼 것 둘:**
- 틈을 0.03 → 0.05로 올렸다
- **화면만 좌우로 물러나게** 했다(`screenInsetRatio` 0.08). 간판은 본체 폭을 꽉 채우고
  화면은 물러나, 어두운 테두리가 화면 삼면을 감싼다 — "캐비닛 얼굴에 박힌 디스플레이"로
  읽힌다

화면이 좁아진 만큼 amber 면적이 줄어 본체를 0.56×0.62 → 0.58×0.64로 키웠다.
`accentCoverage`를 `IconGeometry`의 계산 프로퍼티로 옮겨 물러난 만큼을 빼고 재게 했다 —
테스트가 실제로 칠해지는 넓이를 재도록.

## 조작판이 그림자로만 보였다

`surfaceRaised`(#13151F)는 플레이트 그라데이션과 거의 같은 밝기라, 애써 만든 계단이
보이지 않았다.

**바꾼 것:** 조작판을 `line`으로 칠하고, 버튼은 그보다 어두운 `surfaceBase`로 뒤집었다.

## 16px에 흙탕물 띠가 생겼다

본체 높이의 5%인 틈이 16px에서 1픽셀 아래로 내려가, amber 위에 갈색 얼룩으로 뭉갰다.
구조를 보여주는 게 아니라 실루엣을 더럽혔다.

**바꾼 것:** 단순화 단계를 **셋**으로 늘렸다. 계획은 둘이었다(글자 64↑, 버튼 256↑).

| 요소 | 나타나는 크기 |
|---|---|
| 플레이트 · 본체 · 조작판 실루엣 | 전부 |
| 얼굴 구조(마퀴·틈·화면) **+ 경첩 글자** | 64px 이상 |
| 조작판 버튼 | 256px 이상 |

얼굴 구조와 글자는 **같은 임계값을 공유한다.** 갈라 두면 둘 중 하나가 어중간하게
남는다 — 구조 없는 글자는 amber 판 위의 얼룩이고, 글자 없는 구조는 정체를 알 수 없는
줄무늬다. `theLetterAndTheFaceStructureAppearTogether`가 이 공유를 고정한다.

## 검증

- `swift test` **559개 통과** (신규 20개: `IconGeometryTests` 18, `ModuleBoundaryTests` 2)
- `swift run IconForge` → 10장, `iconutil` → `.icns` 305KB
- `make-app.sh`가 만든 번들에 아이콘이 들어가고 `codesign --verify --strict` 통과
- `verify-bundle.sh`가 아이콘 **없는** 번들을 실제로 거부한다 (지워서 확인)
- 눈으로 확인: 16 · 64 · 128 · 512px, 그리고 번들에서 꺼낸 `.icns` 디코드

## 남은 것

- **macOS 26의 `.icon`(Icon Composer) 형식은 쓰지 않았다.** 고전 `.icns`는 정상 동작하지만
  라이트/다크/틴티드 변형을 자동으로 받지 못한다. 필요해지면 같은 `IconGeometry`에서
  뽑는 것이 다음 단계다.
- **`docs/icon-128.png`는 생성 파이프라인 밖이다.** 커밋된 바이너리라야 GitHub README에서
  보이기 때문이다. 팔레트나 기하를 고치면 손으로 갱신해야 하고, 그 방법은
  `scripts/make-icon.sh` 상단 주석에 적어 뒀다.
- **Dock·Finder 실물 확인은 하지 않았다.** 확인하려면 사용자의 화면을 통째로 캡처해야
  하는데 그 화면에는 사용자의 작업 내용이 담긴다. 대신 번들 안의 `.icns`를 디코드해
  같은 그림이 나오는지 확인했고, `verify-bundle.sh`가 매 빌드에서 존재와 형식을 검사한다.
