# 1920×1080 레이아웃 개편 · 토큰 갱신 UX — 검증 기록

두 작업의 자동 검증 범위와, 테스트로 덮을 수 없어 눈으로 확인한 것을 남긴다.

## 무엇을 바꿨나

| 영역 | 전 | 후 |
|---|---|---|
| 창 | `.windowResizability(.contentSize)` + 최소 720×480 → 사실상 최소 크기로 열림 | `.contentMinSize` + `.defaultSize` 1600×960, 최소 1120×720 |
| 치수·활자 | 9~13pt와 12/20pt 여백이 40여 곳에 하드코딩 | `LayoutTokens`(ArcadeCore) → `ArcadeMetrics`(ArcadeUI), 창 폭 기준 3밀도 |
| 아케이드 플로어 | 납작한 카드 3장을 좌상단에 가로로 늘림 | 세로형 업라이트 캐비닛(간판·화면·조작판) 그리드, 플로어 한가운데 정렬 |
| 만료 대응 | 배너의 유일한 출구가 로그아웃 → 사이트·이메일까지 소실 | 배너에서 갱신 시트, 토큰만 입력. 사이트·이메일은 `SignInHint`로 보존 |
| 워드마크 | 플로어는 `▨ ARCADE FLOOR ▨`, 로그인 화면은 평범한 `Text("JIRA…")` | `JirarcadeWordmark` 하나 — 경첩 글자만 강조색, 두 화면이 공유 |

## 자동 테스트로 덮은 것

- `ArcadeCoreTests/LayoutTokensTests` — 밀도 경계값, 모든 토큰의 밀도별 단조 증가, marquee 단계 클램프,
  트래킹이 marquee에만 붙는지, 창 상수가 의도한 밀도에 떨어지는지, 캐비닛·티켓 카드의 종횡비
- `ArcadeAppTests/SignInHintTests` — 힌트 왕복·손상값 거부, 로그인 시 저장, 로그아웃 후 생존,
  `forgetAccount()`가 지우는지, Keychain 유실 시 힌트만으로 갱신 모드가 뜨는지,
  기존 사용자 이관(자격증명을 읽는 시점에 힌트를 채움)
- `ArcadeAppTests/TokenRenewalTests` — 갱신 성공 시 `.ready` 복귀와 새 토큰 저장, 거부 시 `.expired` 유지,
  재시도 성공 시 옛 문구 제거, 미러·이벤트 로그 보존, 동기화 루프 자체 시작, 힌트/빈 토큰 방어
- `ArcadeCoreTests/WordmarkTests` — 세 조각이 이름을 이루는지, 경첩 글자가 **정말로** 두 단어가 공유하는
  글자인지(4 + 6 − 1 = 9), 경첩이 한 글자인지
- `ArcadeAppTests/ModuleBoundaryTests` — ArcadeUI에 하드코딩된 폰트 크기 금지, 모든 시트가 테마와 밀도를
  함께 재주입하는지, 만료 배너에 갱신 진입점이 있는지, 로그인 화면이 힌트를 읽는지,
  제품 이름을 직접 쓰는 뷰가 없는지, 워드마크가 플로어와 로그인 화면 양쪽에 있는지

`ArcadeUI`에는 테스트 타깃이 없다. 그래서 판단(숫자·밀도)은 `ArcadeCore`에 두고, 뷰 배선은
소스 텍스트 검사로 지킨다 — 기존 색 리터럴 검사와 같은 방식이다.

## 눈으로 확인한 것 (2026-08-24, 1920×1080 외장 디스플레이)

- [x] 첫 실행에서 창이 1600×960으로 열린다 (저장된 프레임이 있으면 `FirstWindowResizer`가 한 번만 다시 잡는다)
- [x] 아케이드 플로어: 캐비닛 세 대가 세로로 서고 플로어 한가운데 정렬된다
- [x] 캐비닛의 어트랙트 화면 밴드가 `surfaceBase`로 패여 보이고, 줄이 세로 중앙에 놓인다
- [x] 하단 스코어보드 레일이 한 줄에 들어간다 (시즌 LV·XP바·통산·동기화 시각·설정·새로고침)
- [x] 퀘스트 보드 전체 화면: HUD 한 줄, 카드 172×138, 축 눈금선이 보인다
- [x] 창을 1120×720으로 줄여도 HUD가 한 줄에 남고 카드가 겹치지 않는다 (compact 밀도)
- [x] 초기 로딩 인디케이터가 화면 정중앙에 뜬다
- [x] 플로어 간판: 워드마크의 경첩 글자만 강조색으로 뜨고, 그 아래 화면 이름, 그 아래 전구 줄
- [x] 로그인 화면 **첫 연결** 모드 — 입력란 셋, 저장된 연결 패널 없음
- [x] 로그인 화면 **토큰 갱신** 모드 — 사이트·이메일이 읽기 전용 패널로, 토큰 입력란 하나,
      `다른 계정으로 연결` / `연결`(빈 토큰이라 비활성)

main의 이월 줄(커밋 `aade9e7`)과 합치면서 `ticketCardHeight`를 (112, 124, 138)에서
(120, 142, 162)로 다시 잡았다 — 이월 줄이 compact에서 104pt 콘텐츠 박스를 요구하는데
112pt 카드로는 96pt밖에 나오지 않기 때문이다. 위 목록은 138pt일 때 본 것이라 카드 높이가
걸린 항목을 세 밀도에서 다시 봤다(스텁 데이터로 `RootView`만 띄우는 하니스, 티켓 9건에
마감일·이월·상태 메뉴를 모두 얹은 상태):

- [x] 1600pt(wide): 카드가 162pt로 그려지고 아래로 넘치는 줄이 없다
- [x] 1400pt(regular): 142pt, 마찬가지
- [x] 1160pt·1120pt(compact): 120pt, HUD가 한 줄에 남고 레인 넷이 겹치지 않는다

세 밀도 모두 가장 빠듯한 상태에서 콘텐츠 아래로 5pt 안팎이 남았다. 다만 마감일과 이월이
**함께** 뜨면 요약이 2줄이 아니라 1줄로 접힌다 — 카드 예산이 그 조합에서 요약의 둘째 줄까지
품지는 못한다는 뜻이다. 높이를 올리기 전에도 같았으므로 이번 변경이 만든 것은 아니다.

로그인 화면 두 모드는 실제 자격증명을 건드리지 않고 확인했다: `JirarcadeApp.swift`의 저장소를
인메모리 구현으로 잠시 바꿔 빌드하고, 확인이 끝난 뒤 원래대로 돌렸다. Keychain은 읽지도 쓰지도 않았다.

### 확인하지 못한 것

- **라이트 테마의 경첩 글자 대비.** 다크에서는 호박색 대 거의 흰색이라 확연하지만, 라이트에서는
  accent가 어두운 갈색(`#8F4E00`, 밝은 배경 대비를 맞춘 값)이라 `inkPrimary`와의 차이가 색상뿐이다.
  팔레트를 바꾸지 않는 한 더 벌릴 수 없고, 팔레트 변경은 이번 범위 밖이었다.
- **전이 실패 카드·백필 진행 줄의 새 밀도.** 재현하려면 Jira 쓰기를 실패시켜야 해서 넘겼다.

## 남은 것 (이번 범위 밖)

- 정체일이 축 상한을 넘는 티켓(실측 500~775일)이 전부 축 끝에 몰려 한 레인이 수천 pt로 자란다.
  `LanePacker`의 문제가 아니라 축 상한과 그 너머를 어떻게 보여줄지의 문제다.
- 캐비닛의 어트랙트 화면은 아직 텍스트 두어 줄이다. 실제 아케이드처럼 게임을 미리 보여주려면
  캐비닛이 자기 요약 뷰를 제공해야 한다.
- 전구 줄은 정지해 있다. 진짜 마퀴는 전구가 흐르지만, 이 헤더는 퀘스트 보드에서 돌아올 때마다
  다시 그려지므로 매번 재생되는 연출은 아케이드가 아니라 소음이 된다. 넣는다면 `reduceMotion`을
  존중하는 1회성 점등이어야 한다.
