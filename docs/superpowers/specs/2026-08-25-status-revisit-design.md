# 되돌아온 티켓을 카드에 드러낸다

이슈 #6. 상태를 왕복시키면 XP는 막히는데 정체일은 리셋된다.

## 1. 문제

이 앱의 존재 이유는 "이 티켓이 며칠째 멈춰 있었는가"다. 정체일이 화면의 주 구조이고 축 위 위치를 정한다.

그런데 그 값은 아무 방어 없이 지워진다.

| | XP | 정체 기준선 |
|---|---|---|
| 되돌림(10분 창 안) | `AbuseGuard.voidReverts`가 양쪽 다 0점 | **그대로 밀린다** |
| 같은 전이 반복(24시간 창) | `voidDuplicates`가 두 번째부터 0점 | **그대로 밀린다** |
| 그 밖의 모든 상태 변화 | 규칙대로 채점 | 밀린다 |

`StatusTimeline.apply`는 `.statusChanged`면 무조건 기준선을 옮긴다. 예외가 없다.

`AbuseGuard.voidReverts`는 왕복을 **이미 감지한다** — 10분 창 안의 정확한 역방향 쌍(`earlier.fromStatus == later.toStatus && earlier.toStatus == later.fromStatus`). 정보는 다 있는데 시간축이 확정된 **뒤에** 돌고 XP만 만진다.

그래서 한 쌍의 이벤트를 한 층은 "없던 일"로, 다른 층은 "진짜 움직임"으로 취급한다. **그 불일치가 이 이슈의 뿌리다.**

## 2. 무엇을 하지 않기로 했나

**기준선 규칙은 바꾸지 않는다.** 3주 동안 진행 중 ↔ 검토를 오간 티켓의 정체일은 계속 "마지막 상태 변화 이후"다.

기준선을 첫 진입 시각으로 되돌리는 안도 검토했다. 왕복하는 티켓이 오래될수록 커져서 실제 공전을 반영한다는 장점이 있으나, 리뷰 반려 후 **진짜로 재작업해도** 숫자가 줄지 않아 "이거 지금 하고 있는데"라는 불만이 생긴다. 숫자는 정직하게 두고 맥락을 따로 드러내는 쪽을 택했다.

**되돌림 무효의 창(10분)이나 중복 무효의 창(24시간)도 바꾸지 않는다.** 이 설계는 기존 규칙의 판정을 **가져다 쓸 뿐** 새 임계값을 만들지 않는다.

## 3. 무엇을 하나

### 3.1 되돌림 감지를 두 층이 함께 쓴다

`AbuseGuard.voidReverts` 안에 있는 판정을 순수 함수로 꺼낸다.

```swift
/// 되돌림 쌍에 속한 이벤트의 **위치**. 같은 티켓에서 A→B 직후 창 안에 B→A가 관측되면
/// 그 둘을 한 쌍으로 본다.
///
/// `DomainEvent`에는 안정적인 식별자가 없고 `Hashable`도 아니라 위치로 가리킨다.
/// 반환값은 **넘긴 배열 기준의 인덱스**이므로, 호출자는 인덱싱할 그 배열을 그대로 넘겨야 한다.
public enum RevertDetector {
    public static func revertedIndices(
        in events: [DomainEvent],
        windowMinutes: Double
    ) -> Set<Int>
}
```

`AbuseGuard`는 이 함수로 무효화할 쌍을 찾고, 시간축과 §3.2의 계산은 같은 함수로 **건너뛸** 쌍을 찾는다. 한 쌍을 두 층이 다르게 볼 수 없게 된다.

**이것이 이 설계의 유일한 구조 변경이다.** 지금까지 채점 층과 시간축 층은 서로를 몰랐고 그건 의도였다 — 채점 규칙이 바뀌어도 시간축은 흔들리지 않아야 하니까. 그 분리를 통째로 깨지 않고, **"이 이벤트 쌍은 없던 일이다"라는 사실 하나만** 공유한다. 방향은 여전히 한 쪽이다: 시간축이 채점을 참조하지 않고, 둘 다 같은 감지기를 참조한다.

### 3.2 되돌아온 횟수를 센다

`SprintHistory.summarize`와 같은 모양의 순수 함수를 `ArcadeCore`에 둔다.

```swift
public enum StatusRevisits {
    /// 티켓별 "이미 거쳤던 상태로 돌아온" 횟수.
    public static func counts(
        from events: [DomainEvent],
        revertWindowMinutes: Double
    ) -> [String: Int]
}
```

규칙:

1. 티켓별로 `.statusChanged` 이벤트를 `observedAt` 순으로 본다.
2. **되돌림 쌍의 두 이벤트는 건너뛴다** — `RevertDetector`가 판정한 것.
3. 살아남은 첫 이벤트의 `fromStatus`로 집합을 연다. 그 상태는 이미 거쳐 온 것이다.
4. 이벤트마다 **검사한 뒤에 넣는다.** `toStatus`가 이미 집합에 있으면 횟수를 1 올리고, 그다음 집합에 넣는다.

   순서가 반대면 첫 이벤트조차 자기 자신 때문에 왕복으로 세어진다. 검사가 먼저다.
5. 돌아온 적이 없으면 그 티켓은 맵에 넣지 않는다(0을 담지 않는다).

예시 — `진행 중 → 검토 → 진행 중 → 검토`(되돌림 창 밖):

| 이벤트 | 집합(검사 시점) | toStatus | 왕복? | 집합(넣은 뒤) |
|---|---|---|---|---|
| (시작) | — | — | — | `{진행 중}` |
| → 검토 | `{진행 중}` | 검토 | 아니오 | `{진행 중, 검토}` |
| → 진행 중 | `{진행 중, 검토}` | 진행 중 | **예 (1)** | 그대로 |
| → 검토 | `{진행 중, 검토}` | 검토 | **예 (2)** | 그대로 |

결과 `2`.

`fromStatus`나 `toStatus`가 `nil`인 이벤트는 건너뛴다. 상태를 모르면 거쳤는지도 판정할 수 없다.

### 3.3 시간축이 되돌림 쌍을 건너뛴다

`StatusTimeline.latestStatusEntry`가 되돌림 쌍을 제외하고 맵을 만든다.

```swift
public static func latestStatusEntry(
    from events: [DomainEvent],
    revertWindowMinutes: Double
) -> [String: Date]
```

`ScoreEngine.recompute`의 순회도 같은 제외를 거쳐야 한다 — 그러지 않으면 보드가 쓰는 최종값과 채점이 쓰는 시점별 값이 다시 갈린다. `StatusTimeline.apply`가 갱신 규칙의 유일한 정의라는 성질은 유지한다.

**결과**: 잘못 눌러 3초 만에 되돌린 티켓은 정체일을 잃지 않는다. XP가 이미 0인 그 쌍을 시간축도 없던 일로 본다.

## 4. 화면

### 4.1 새 줄을 만들지 않는다

`BoardMetrics`의 주석이 카드가 이미 초과 예약 상태임을 기록하고 있다 — 마감일과 이월이 함께 뜨면 `lineLimit(2)`인 요약이 한 줄로 접힌다(세 밀도 모두). 일곱 번째 줄은 요약을 더 밀거나 `ticketCardHeight`를 올려야 하고, 그 값은 모든 레인 높이에 곱해진다.

**정체일 라벨 옆에 붙인다.** 맨 윗줄은 `[등급] ─ Spacer ─ [정체일]`인 `HStack`이라 세로 공간을 쓰지 않는다.

```
STALE                    ⇄3 ~18d
DEMO-9074
[통합] 전체 통계 기반 마케팅…
19일 지남
↻ 스프린트 13회
상태 옮기기 ⌄
```

자리가 맞는 이유는 공간 때문만이 아니다. **`⇄3`이 수식하는 대상이 바로 옆의 `~18d`다.** "이 18일은 3번 돌아온 뒤의 18일이다"가 한 줄에서 읽힌다. 카드 아래쪽에 별도 줄로 두면 그 연결이 끊긴다.

되돌아온 적이 없으면 아무것도 그리지 않는다. `↻ 스프린트`와 같은 규칙이다 — 0은 아무것도 말하지 않으면서 자리만 차지한다.

### 4.2 툴팁

카드에는 이미 `.help()`가 있고 추정 여부에 따라 문장이 갈린다. 왕복이 있으면 그 사실을 덧붙인다.

- 되돌아온 적 없음 → 지금과 같다
- 되돌아온 적 있음 → `"이미 거쳐 간 상태로 3번 돌아왔습니다"`를 앞에 붙이고, 추정치면 기존 문장도 잇는다

문장 조립은 뷰의 몫이다. 뷰는 숫자와 불리언만 읽는다 — 판단은 `ArcadeCore`가 끝냈다.

### 4.3 표기에 대한 유보

`⇄3`은 라벨이 없다. `↻ 스프린트 13회`와 달리 처음 보는 사람이 뜻을 모를 수 있다. 툴팁이 그것을 메우지만 호버해야 한다.

이 설계는 `⇄3`으로 간다. 자리가 없어서다. 육안 검증에서 읽히지 않는다고 판단되면 대안은 두 가지다 — 정체일 라벨 자체를 `18d⇄`로 바꾸거나, 카드에서 빼고 상세 시트에만 두는 것.

## 5. 데이터 경로

이월 횟수는 미러(`ObservedIssue`)에서 오지만 **왕복 횟수는 이벤트 로그에서 온다.** `statusEnteredAt`과 같은 길을 간다.

```
ArcadeStore.loadEvents()
  → StatusRevisits.counts(from:revertWindowMinutes:)     [ArcadeCore]
  → AppModel.statusRevisits: [String: Int]               [ArcadeApp]
  → BoardLayout.snapshot(..., statusRevisits:)           [ArcadeCore]
  → BoardSlot.revisits: Int                              [ArcadeCore]
  → TicketCardView                                        [ArcadeUI]
```

`AppModel`이 `statusEnteredAt`을 만드는 자리(`AppModel.swift:737`)에서 함께 만든다. 로그를 두 번 돌지 않도록 한 번의 순회로 둘을 만드는 것도 가능하나, **먼저 나눠서 만들고** 실제로 느린지 재본 뒤에 합친다. 티켓 49건에 이벤트 5,900건 규모에서 두 번 도는 비용은 측정 없이 최적화할 값이 아니다.

`signOut()`이 `statusEnteredAt`을 비우는 자리에서 함께 비운다.

## 6. 채점은 움직이지 않는다

이 계획의 어떤 값도 `XpAwarder`·`HygieneCalculator`·`ScoreEngine`·`AbuseGuard`의 **입력이 되지 않는다.** `BoardSlot.revisits`는 표시 전용이다.

다만 §3.3은 채점에 **간접적으로** 영향을 준다. `statusEnteredAt`이 달라지면 `wakeXP`의 정체 배수가 달라지기 때문이다.

**그 변화는 의도된 것이다.** 되돌림 쌍이 기준선을 밀지 않게 되면, 그 뒤의 전진 전이는 "3주 정체를 깬 것"으로 채점된다 — 지금은 "방금 옮긴 것을 또 옮긴 것"으로 채점되어 배수가 1에 가깝다. 후자가 틀렸다.

이 영향의 크기를 실제 로그로 재고 스펙에 적는다. 예상은 작다 — 되돌림 쌍이 흔하지 않고, 흔하다면 그것 자체가 이 이슈의 심각도를 말한다.

## 7. 테스트 전략

| 계층 | 무엇을 |
|---|---|
| `ArcadeCore` | `RevertDetector`가 창 안/밖, 정확한 역방향/아닌 것을 가르는지 |
| `ArcadeCore` | `StatusRevisits.counts`가 되돌림 쌍을 건너뛰고 진짜 복귀만 세는지 |
| `ArcadeCore` | `latestStatusEntry`가 되돌림 쌍을 건너뛰어 기준선을 지키는지 |
| `ArcadeCore` (회귀) | `AbuseGuard`가 추출 전과 **같은 결과**를 내는지 — 기존 테스트가 무편집 통과해야 한다 |
| `ArcadeCore` (회귀) | 실제 로그 규모에서 채점 총합이 얼마나 움직이는지 |
| `ArcadeApp` | `signOut()`이 `statusRevisits`를 비우는지 |
| `ArcadeUI` | 테스트 타깃 없음. 판단을 두지 않는다 |

테스트는 Swift Testing(`@Test` / `#expect`)을 쓴다. 조직 특정 정보를 넣지 않는다 — `example.atlassian.net`과 `DEMO-`만.

## 8. 완성 정의

- [ ] 되돌림 쌍(10분 창)이 정체 기준선을 밀지 않는다
- [ ] 되돌림 쌍은 왕복 횟수에도 세지 않는다 — 오조작이 티켓을 "왕복 중"으로 낙인찍지 않는다
- [ ] 창 밖의 왕복은 기준선을 밀고, 카드에 `⇄N`이 뜬다
- [ ] 되돌아온 적 없는 티켓에는 아무것도 그리지 않는다
- [ ] 카드에 새 줄이 생기지 않는다 — 요약이 지금보다 더 접히지 않는다
- [ ] `AbuseGuard`의 기존 테스트가 **무편집으로** 통과한다
- [ ] `.touched`가 여전히 0점이고, 왕복 횟수가 채점 입력이 아니다
- [ ] `signOut()`이 새 상태를 지운다
- [ ] 실제 로그에서 채점 총합이 얼마나 움직였는지 기록돼 있다
- [ ] 전체 테스트가 통과한다

## 9. 남는 위험

- **`⇄3` 표기가 읽히지 않을 수 있다**(§4.3). 육안 검증 항목으로 등록한다.
- **되돌림 감지가 체인을 다루지 않는다.** A→B, B→A, A→B가 모두 창 안에 있으면 `voidReverts`는 첫 쌍만 매칭하고 멈춘다. 지금 동작이 그러하고 이 설계는 그것을 바꾸지 않는다 — 바꾸면 채점 결과가 움직인다. 별도 이슈로 둘 값어치가 있는지는 실제 로그를 보고 판단한다.
- **왕복 횟수에 창이 없다.** 3년 전에 한 번 돌아온 티켓도 `⇄1`이 붙는다. 시즌이나 최근 N일로 자르는 안이 있으나, `↻ 스프린트`도 전체 이력을 세므로 일관성을 택했다. 실제 데이터에서 과하면 그때 자른다.
